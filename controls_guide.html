Controls — User Guide

Overview

The Controls page is used to manage rally timing and results. It displays the controls for the selected rally day, calculates expected times, records actual times, calculates penalties and prepares the results for review and printing.

The control structure comes from the rally route and Schedule. When a route is based on Mapping, controls are added and positioned in Mapping, then imported into Schedule. Controls displays the resulting STC, Start STC, Marshal and Open Control cards automatically.

Actual control times can be entered manually or downloaded from the app’s Google-based control-data system. Entrants may also submit STC times using the STC Recorder mobile app.

Most values are calculated automatically. Blue text represents non-editable data. The normal editable items are actual times and Clerk of the Course penalties.

The page can be used during the rally to review incoming timing data and afterwards to check penalties, exclude a control where justified, and publish the results.

The page has a Normal/Compact button. Toggling this changes the page size.

Key items

  • A card is shown for each control defined in the Schedule: STCs, Marshals, Open Controls, and Start STCs. Each is numbered as per the schedule sequence.
  • Controls are presented per day using the day selector.
  • Expected times (ETA) are calculated automatically based on the entrant's speed group and route allocation.
  • Actual times (ATA) can be entered manually or automatically using the Controls Data tool.
  • Scores are calculated from the difference between ATA and ETA. Penalties are limited to 600 seconds early or late.
  • Save and Load use the shared Rally Workspace and save or restore the complete rally project, including Admin, Mapping, Schedule and Controls data.
  • Print results: presents print options, including a summary for multiple rally days.
  • Export creates a spreadsheet file for further review or tailoring.

Page layout

Purpose: To provide a clear, card-based layout for entering control times and viewing the calculated results.

Description

On the left of the page is the listing of entrant details, including their speed group, route allocation (if more than 1 set - refer Admin) Rally number and lastly their total error score, these fields cannot be edited.

The entrant Rally number when clicked will open a card enabling the results for that entrant to be entered sequentially rather than panning to individual control cards across the page.

To enable comparison of control times to start times, click Total Score, the column below will change to Start Time, toggle again to revert.

To the right of the entrant details is an optional card for the entry of COC penalties, the “offence” and the points to be awarded, to include these penalties in the final score COC must be checked.

Note: When two routes have been selected and a route is missing controls, an Rt. warning is presented in place of ETA timing.

Day selection

Purpose: To select which rally day is being viewed and edited in controls, when you select an alternate day the schedule for that day will be automatically selected, likewise the same applies selecting a day in schedule, the controls for that day will be presented. If a rally day the page will open set to that day.

How to use:

  • Use the Day selector at the top of the page.
  • Select the required day.
  • The visible cards and data update immediately.

Control cards

Purpose: Each card represents one control point and is used to calculate times and scores for each of the entrants based on rally number and speed group.

Card types:

  • STC — Self time control cards as defined in the Schedule
  • Marshal — records arrival times at a fixed control point.
  • Open Control — similar to Marshal but entrants can arrive at the control early without penalties, up to 10 minutes early.
  • Start STC — resets the timing baseline, entrants provide their leaving time from the control. Control ETA timings following a Start STC are automatically calculated based on the Start STC time submitted.

STC, Marshal and Open Control cards

Purpose: To record arrival times (ATA) and calculate penalties, penalties are limited to +/- 600 seconds, the total score is the absolute sum of penalties.

Expected times (ETA) are calculated and cannot be edited (blue font).

ETA time calculations.

  • STC - elapsed time from Schedule based on SG of entrant.
  • Marshals and Open Controls – entrant start time + elapsed time from Schedule based on the SG of entrant.
  • If a Start STC precedes the control: ETA = Start STC time + elapsed time from Schedule.

Note: If a Start STC time has not been entered, then following card ETA times will remain blank.

How to use:

  • Review the calculated ETA.
  • Enter or download ATA times as recorded by the entrants and marshals. Downloaded times automatically populating the cards.
  • Scores update automatically.

Starts

Starts when selected will present the starting times for each entrant, enabling any timing checks to be undertaken.

Start STC cards

Purpose: A Start STC resets the rally timing. All following ETA times are calculated from this new starting point. STC and Marshal ETA times being calculated based on the Start STC time submitted.

How to use:

  • Enter or download the Start STC time provided by each entrant.
  • Once entered, downstream ETAs update automatically.
  • Until a Start STC time is entered, expected times for later controls cannot be calculated.
  • Start STC cards do not record penalties themselves.

Note: when a Start STC is incorporated into the schedule, later marshal timings are no longer predictable, so this needs to be appreciated and arrangements made accordingly. Entrants can also be advised that they must leave a Start STC by a given time, thus marshal times can be more easily managed.

Entrant guidelines: At a Start STC the schedule time is 00:00:00, a timing reset in the schedule, the timings to the next instructions being an increment from this fresh start.

The time to be recorded at the Start STC by the entrant is the elapsed time, based on the rally master time since the start of the day. When they reach a next STC they again record their rally master time.

In order to track their progress in terms of time from the Start STC they will need to either start a separate stop watch on leaving the Start STC and track their progress based on the schedule timings or add the schedule times to their Start STC time and use rally master time.

STC Recorder timing mode

The Controls setup determines how the shared STC Recorder mobile app operates.

Button mode

Entrants press and hold the STC button as they pass each control. The recorded button time is submitted as the entrant’s STC time.

Where GPS support has been configured, GPS evidence may also be recorded in the background for later audit. The entrant does not need to operate or review this background data during the rally.

GPS mode

The recorder operates as a GPS timing logger. Detected STC times can be reviewed before submission but cannot be manually edited.

After the submitted data is downloaded, timing details can be reviewed in Controls where required.

Tracking with the STC Recorder

Purpose: Tracking allows the organiser to follow an entrant’s progress using periodic GPS position records sent by the STC Recorder mobile app. Tracking is optional and is controlled separately for each uploaded Controls package.

Enabling or disabling Tracking

  • Use the Tracking checkbox beside the STC Mobile App sharing controls.
  • When Tracking is selected, newly generated STC Mobile App links include the Tracking setting.
  • When Tracking is not selected, the recorder operates normally without creating tracking records.

When Tracking records are created

  • Selecting Begin prepares the recorder and starts the countdown to the entrant’s official start time.
  • No tracking records are created during the countdown.
  • Tracking starts when the official start time is reached and the recorder changes to elapsed time.
  • At each tracking period the recorder stores the latest position together with the current tracking time.
  • If there is no connection, records remain safely queued on the phone and are uploaded in order when a connection becomes available.

Managing a Tracking setting change

The Tracking choice is included in the uploaded Controls package and in the STC Mobile App link. If Tracking is selected or deselected after Controls data has already been uploaded, a clear New upload required notice is displayed.

  • Select Upload controls data again.
  • Then re-share the STC Mobile App link so entrants receive the revised Tracking setting.
  • If the Tracking selection is changed back to the last uploaded state, the package is aligned again and no new upload is required.

Note: Changing Tracking does not alter the rally timing or results calculations. It changes only whether the shared STC Recorder package collects and submits tracking positions.

Using the STC Recorder mobile app

The STC Recorder is shared with entrants as a rally-day link from the Controls Data card. Each link contains the rally title, day, date, timing mode and the STCs to be recorded for that day.

Organiser workflow

  • Finalise the entrants, controls and timing mode for the rally day.
  • Select Upload controls data if the Controls Data button indicates that the current upload is out of date.
  • Use the STC Recorder sharing option to send the day-specific link by WhatsApp, email or copied link.
  • For the clearest operation, share only the link for the next active rally day.
  • If the controls or timing mode change after sharing, upload the revised data and send the updated link.

Daily validity

Each recorder package is guarded by its rally date. It is active from 03:00 on the rally date until 02:59 the following morning.

  • Before the active window, the recorder displays Not yet active.
  • After the active window, it displays Expired.
  • Outside the active window, Begin, STC recording, review, editing and submission are blocked.
  • The entrant must open the new link supplied for the following rally day.

The recorder app may remain stored in the phone browser, but the old day package cannot be used after it expires. Opening the following day’s link loads that day’s controls automatically. Entrants do not need to clear browser data or reinstall the app.

Entrant use

  • Open the link supplied for the current rally day.
  • Check the rally title, day and date shown at the top of the recorder.
  • Complete the finger test and enter the required entrant details.
  • Use the recorder according to the selected Button or GPS mode.
  • Review and submit the recorded times before the daily package expires.

Recommended practice: issue a fresh recorder link for each rally day. Several future-day links can be shared in advance, but daily sharing reduces the chance of entrants opening the wrong link or using an outdated control package.

Result Audit

Purpose: A tool that will highlight result errors that exceed the audit value selected, to use the tool first select it (check) and then enter a value. Should a control have excessive errors which could be a result of an unexpected route delay, then that control can be removed from the overall results by unchecking it. All control cards are normally checked. The printed result from an unchecked control will be zero.

Typical workflow

  • Build the route and controls in Mapping, or create them manually in Schedule when no mapped route is being used.
  • Import the mapped route into Schedule and complete the schedule timings and instructions.
  • Open Controls on rally day.
  • Select the correct day.
  • Upload your control data and the share links to entrants and marshals.
  • Later review the returns submitted, then download.
  • Enter/download the ATA times provided by each entrant and marshals.
  • Review scores, optionally make use of the Audit tool.
  • Deselect any controls to be excluded from the day’s result.
  • Print results.

Controls data

The Controls Data card connects the rally project to the Google Forms and Google Sheets created through the Admin setup.

Entrants and Marshals submit control times using shared online forms or the STC Recorder mobile app. Google stores and organises the responses so they can be reviewed and downloaded into the correct control cards.

The one-time Google connection must first be completed through the Admin Entries card. When the connection is available, the Controls Data card shows Connected.

If a prior upload of data becomes out of date, changes made since the last upload then the Controls data button will wink, examples: an added entrant, driver name change, control changes or a change of mode Manual/GPS. A new upload must be undertaken.

Card buttons, uploading and sharing links

  • Upload controls data used when all entries and schedule planning have been finalized, or there has been a change since a last upload.
  • Entrant and Marshal links, either Copy link , Email link or WhatsApp (WA) links to the results forms to be completed.
  • Day-specific links are provided for sharing the STC Recorder mobile app. Send the link for the active rally day and issue a fresh link for each following day.
  • To WA links you will need to have WA on your computer, you then send the link to yourself, which you can then share as required. Consider setting up a WA group of entrants, Marshal links will need to be sent separately, or a marshal group.

Card buttons, reviewing and downloading submitted data

  • View form responses – opens the Google form responses page.View mobile responses – opens the Google responses page from mobile submissions.
  • Select Open controls data this opens the Google rally worksheet, select the required tab, review the data awaiting download.
  • Download controls data – only enabled when there is data available for download, select to import data populating the control cards.

Notes: When a download is performed it will overwrite any previously captured data.

Entrant results are checked against their Surname and Rally number, if an error is made, that submission will not be added to the worksheet data tab ready for download, it will be included in the error list tab, select Open controls data to review.

Entrants and Marshals can submit more than one return, the last being used.

Printing of results

Select Print a menu is presented, offering options including overall result from rally days.

Result data can also be exported for further processing.

Save and Load

Save and Load are common to all pages. Selecting Save stores the complete rally project in the Rally Workspace folder based on the rally title.

Load when selected will present a file picker to enable the selection of which saved rally file is to be loaded, it must be emphasized that loading will overwrite your current work. Note: a warning is shown before loading a file.
