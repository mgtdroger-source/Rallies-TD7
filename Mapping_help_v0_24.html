Mapping guide

Mapping — Route Mapping

The Mapping page is used to build or edit the rally route map, keep the route points in driving order, draw control trip lines, import Field Data, and save the editable map file for later route work.

The Mapping page is used to build or edit the rally route map, keep the route points in driving order, import Field Data, and save the editable map file for later route work.

Overview

The page has two main areas: the left panel for route controls and point details, and the map area for placing, checking, and editing points. The main action buttons are arranged in a compact layout, with Fit Route and Help centred for quick access.

The map banner shows two context pills. Schedule shows the active rally, day, and route. Map shows the description of the mapping file currently open on the page.

Mapping is integrated with the active rally project. Each rally day and route has its own Mapping working data, and Route 1 and Route 2 are kept separately.

TD2 uses the same core Mapping tools but keeps the planning workflow simpler. The map banner identifies the Mapping file currently open, without the TD7 Schedule comparison and mismatch features.

Day and Route selector

The selector at the top of the map combines the rally day and route into one control. Route choices are grouped beneath their day and include the date, for example 04 Sep - Route 1 and 04 Sep - Route 2.

Admin controls which routes are available. If Admin is set to one route, only Route 1 is shown. If Admin is set to two routes, Route 1 and Route 2 are shown. Mapping does not create extra selectable routes from old local map data.

Each valid day/route combination has its own local working map. Before Mapping changes to another selection, the current working map is retained. Selecting another day/route restores the working map belonging to that exact slot.

If Admin is changed from two routes to one, the old Route 2 working map is not deleted; it is simply hidden from the selector. If Route 2 is enabled again later, its previous working map can become available again.

In TD7, selecting a day/route also updates the shared Schedule context. A change made in Schedule is mirrored back to Mapping, so both pages stay on the same day and route.

In TD2, the same selector controls Mapping working maps, but it remains independent of Schedule. TD2 does not use the TD7 Schedule import, comparison, or mismatch workflow.

Normal workflow: select the correct day and route, build or edit the map, enter a clear Map description, and select Save Route. The versioned map file is stored automatically in Maps/Route 1 or Maps/Route 2, based on the active route.

Mapping keeps a separate local working map for Route 1 and Route 2. When the route selector is changed, the working map belonging to that route is restored.

Save Route and Load Route use the folder for the active route. Always check the selected rally day and route before saving or loading a map.

Each time Save Route is used, Mapping creates a new versioned JSON file. The filename is controlled automatically from the rally title, day, route, and save time.

Example:

Deep_South_2026_Day_1_Route_1_map_2026-07-15_1320.json

The Map description is stored inside the file and shown in the wider Map pill together with the saved version date and time. Use a short description that helps distinguish the route version, such as long route save or after STC 3 survey.

Schedule and Map context

The Schedule pill identifies the active rally, day, and route. The Map pill identifies the mapping file currently open on the page.

When Schedule imports a mapped route, it records the exact mapping filename and the map project identity. Mapping compares its current file with that Schedule record.

If the current mapping file is not the exact version last imported into Schedule, Mapping shows Map does not match Schedule beneath the Schedule pill.

When the map is updated, save it and import the revised version into the matching Schedule day and route to clear the warning.

Starting a new map

When a blank route is opened, Add Next WP is already ON. Move or zoom the map to the required starting position, then click the map to place the first waypoint.

The first waypoint becomes the start of the ordered route. Continue clicking the map in driving order to add further waypoints, or turn Add Next WP off when the initial placement is complete.

If the first waypoint is placed incorrectly, select its card or marker and correct it before continuing. Establishing the correct first point helps keep the route order and distances clear from the start.

Route points and order

Each route point appears as a card in the left panel and as a marker on the map. Select a card or marker before editing, inserting after it, or adding related breadcrumb detail.

When a route has many waypoint cards, use the ▼ button beside Save Route and Load Route to jump directly to the controls at the bottom of the left panel. The button changes to ▲ near the bottom so you can return to the top without dragging through the full list.

Route order matters. The saved mapping file keeps the route order, point types, notes, distances, and trip line details.

Waypoints General route points used to shape the route and keep the driven path in the correct order.
Controls STC, Start STC, Marshal, and Open Control points can include notes and optional trip/control line coordinates.

Insert WP After Selected

Use Insert WP After Selected when you need to add a normal waypoint or instruction point into an existing route.

First select the waypoint or control that comes before the new point. Then select Insert WP After Selected. Mapping confirms the insertion position, and the selected card moves to a simple bottom-right card so it does not block the map. Click the map where the new waypoint should be added.

After the new waypoint is added, Insert mode turns off automatically and the bottom-right card closes.

Use Insert WP After Selected for normal route points. Use Breadcrumb for route-shaping points only.

Breadcrumbs

Breadcrumb mode is for sketching or refining the route path between important points.

To add breadcrumbs at the end of the route, turn Breadcrumb ON, click the map in driving order, then turn Breadcrumb OFF when done.

To insert breadcrumbs within an existing route, first select the previous breadcrumb. If the card blocks the map, select Move card to corner. Then turn Breadcrumb ON, click the map to add the new breadcrumb or breadcrumbs, and turn Breadcrumb OFF when done.

When you start adding normal waypoints or surveyed controls, Breadcrumb is automatically turned off. This protects the route from accidental breadcrumb placement while doing normal route editing.

Trip lines and control lines

For STC and Start STC controls, a red trip/control line can be drawn or supplied from field data. This line is the timing/checking reference used later by the rally app workflow.

Field data centre points may be more accurate than manually plotted map points. If replacing a control with imported field data, check that the line is still appropriate and regenerate or redraw the trip line where needed.

Import Field Data

Use Import Field Data to bring in data captured from the Rally Field Tool. Imported controls, waypoints, Trip Marks, notes and Route Survey data are shown first as field-reference information. They do not become part of the formal blue mapped route automatically.

Adding imported details to the route

  1. Select Import Field Data and load the Field Tool file.
  2. The imported controls, waypoints and Trip Marks appear on the map and in the Imported Field Data cards.
  3. Use Zoom, or select the imported point on the map, to review its GPS position and captured note.
  4. From the map popup, use Open Google Earth, Open Maps Satellite View, or Open Maps Street View when you want to inspect the location before accepting it.
  5. If a Trip Mark needs a small position correction, drag its marker on the map before adding it. This is useful when a field run was travelled in the opposite direction and the mark needs to be moved to the correct side of the road for the formal OSRM route. Dragging changes only the Mapping working position of that Trip Mark; the imported Route Survey remains unchanged. The move can be restored with Undo.
  6. If the point belongs in the formal route, select Add to Route. Mapping uses the Trip Mark's adjusted position if it has been moved.
  7. A captured waypoint or control keeps its Field Tool type and note when it is added.
  8. A Trip Mark is added as a normal Instruction waypoint and carries its captured note.
  9. Mapping places the new point into the route according to its position along the mapped route and recalculates the route.

Once an imported point has been added, it becomes a normal Mapping route point and can be edited in the usual way. Imported points that are not added remain field-reference information only and are not supplied to Schedule.

Imported notes are kept with the related waypoint or control. When the saved rally map is later imported into the Schedule page, only the ordered Waypoints and Controls with their notes are used; breadcrumbs are excluded.

If the Field Data contains a Route Survey, Mapping shows it as a separate dotted reference line over the map. The Route Survey is only a field reminder of the road that was driven; it does not alter the formal blue mapped route, route distances, Schedule data, or OSRM routing.

Use Show / Hide to temporarily hide or restore the Route Survey while checking the formal route. The survey data is retained while hidden, and the selected visibility is retained when the Mapping file is saved and reopened.

Clear Imported Field Data removes the remaining imported field-reference data, including the Route Survey. It does not remove or change the formal blue mapped route.

Distance calibration

Distance CAL lets you compare a mapped distance with an independently measured distance, then apply a controlled percentage correction to the rally distances without changing the route geometry.

The comparison and the correction are deliberately separate. The calculated Error % shows what was measured; the Correction % is the value you decide to apply.

Principle: Mapping keeps the raw OSRM/map distance as the underlying route truth. A correction changes the rally distance values only; the raw map distance remains available for checking and audit.

Using Distance CAL

  1. Select Distance CAL at the bottom of the left panel.
  2. Enter the Mapped distance used for your comparison.
  3. Enter the independently Measured distance, for example a Rally Field Tool GPS odometer result, calibrated fifth wheel measurement, or other agreed reference.
  4. Mapping calculates and displays the Error %.
  5. Enter the Correction % (+ / -) you want Mapping to apply. This does not have to be identical to the calculated error.
  6. Select Apply Correction.

Example: if the Mapped distance is 44.000 km and the Measured distance is 44.040 km, the displayed error is approximately +0.091%. You may then choose to apply a correction such as +0.09%.

When calibration is active

  • A red warning is shown at the bottom-left of the map, for example DIST CAL +0.09%.
  • The warning remains visible while the applied correction is not 0.00%.
  • Waypoint/control cards continue to show the corrected Segment and Cumulative rally distances.
  • When a correction is active, the waypoint popup also shows the applied factor and raw map cumulative distance, for example CAL +0.09% · MAP 91.176 km.
  • At 0.00%, the extra CAL / MAP line is hidden.
  • Start STC reset distances and the distances supplied to Schedule use the applied correction.
  • Displayed Mapping distances use the applied correction while the raw OSRM/map distance remains retained for reference.

Apply, reopen and reset

  • After Apply Correction, the entered Mapped distance, Measured distance, calculated Error %, and Correction % are retained.
  • Reopening the Distance CAL card shows the comparison that was used as the reference for the applied correction.
  • Reset 0.00% removes the applied correction, clears the comparison fields, returns Correction % to 0.00, and leaves the Distance CAL card open.
Calibration changes distance values only. It does not move the route, alter OSRM geometry, change waypoint order, or change the GPS coordinates of controls and trip lines.

Mapping and the rally project

Mapping is part of the rally project. Each rally day and route has its own Mapping working data, which is retained with the project.

Route 1 and Route 2 remain separate so each route can be opened and edited independently. Their versioned map files are stored in the matching route folders.

Save Route saves a versioned map file in the active route folder and updates the Mapping working copy for that route.

When the rally project is saved, its Schedule data, active route selection, Mapping data and imported-map identity are saved together as one integrated rally project.

Save Route creates a reusable version of the active map.
Save Project saves the complete rally project, including its integrated Schedule and Mapping data.

Updating Schedule from Mapping

Changes made in Mapping do not alter the Schedule rows until the revised map is imported.

  1. Make the route changes in Mapping.
  2. Select Save Route.
  3. Open Schedule and select the matching day and route.
  4. Select Import Mapped Route.
  5. Select the revised map from the active route folder.
  6. Check that the Map and Schedule identity warning has cleared.
  7. Save the rally project.

Saving the rally project retains the updated Schedule and Mapping data together.

Share Route

Share Route is intentionally simple. It does not create another download or compose an email. It helps you find the already-saved route JSON so Windows can send the file using your normal method.

  1. Save the route first so the required JSON exists in the active route folder.
  2. Select Share Route.
  3. Select Open Route Folder.
  4. In the Windows file window, right-click the required route JSON file and send/share it using Email, or another suitable method available on your computer.
  5. Select Cancel on the Share Route card when finished.
Share Route uses the saved route file. It does not create a duplicate JSON in Downloads.

Sharing a map route with the Field App

The purpose of sharing the Mapping JSON is to get the saved route onto the mobile device used with the Rally Field App for Route Validation.

  1. Finish or update the route in Mapping and select Save Route.
  2. Select Share Route, then Open Route Folder.
  3. Right-click the required route JSON file and send/share it to the mobile device using Email, or another suitable method.
  4. On the mobile device, open the Email or message and download the JSON file.
  5. Open the Rally Field App and select Route Validation.
  6. Select Load Route to Validate, then select the downloaded mapping JSON file.
  7. Select the waypoint where the validation run will start, then use either Start Trip Now for a standing start or Arm Start at Waypoint for an automatic start when that waypoint is detected.

During the run, the Field App uses each waypoint or control's mapped cumulative distance and compares it with the GPS trip distance recorded when the point or trip line is detected. Each updated card shows the mapped distance, GPS distance, and the difference between them.

Trip lines use automatic line-crossing detection. Centre-only waypoints use 30 m radius detection. This allows the route distances to be checked point by point and shows whether the GPS distance remains aligned with the mapped route over the full section.

The saved Mapping JSON is the route file used for Field App validation. Breadcrumbs remain mapping support detail and are not used as validation cards.

Using Mapping with Schedule

A saved rally map is imported into Schedule using Import Mapped Route.

  • When Route 1 is active, the file picker opens in Maps/Route 1.
  • When Route 2 is active, the file picker opens in Maps/Route 2.

The import uses the ordered Waypoints and Controls, together with their notes and mapped distances. Breadcrumbs are not imported because they are Mapping support points used only to shape the route.

Mapped route ownership

Waypoints and Controls imported from Mapping remain owned by Mapping.

  • Mapped distances are locked in Schedule.
  • Controls cannot be added in Schedule when the route is based on an imported map.
  • New STC, Start STC, Marshal and Open Control points must be added in Mapping.
  • Mapped Waypoints and Controls must be moved, changed or deleted in Mapping.
  • After changing the route, save the revised map and import it into Schedule again.

This protects the mapped route structure and prevents Schedule editing from breaking the route order, distances or control positions.

Schedule additions

Schedule may add its own Instruction and Added Time rows around the mapped route.

  • These rows belong to Schedule rather than Mapping.
  • They can be edited or deleted in Schedule.
  • They are preserved when the mapped route is imported again.

Map and Schedule identity

Schedule records the exact imported mapping filename and map identity. Saving a newer map in Mapping does not automatically update the Schedule rows.

Save the revised route, import it into the matching Schedule day and route, check that the warning has cleared, and then save the rally project.
