Tracking guide

Tracking — Live Tracking and Event Replay

The Tracking page shows entrant positions on the mapped event route. Positions are recorded at approximately 30-second intervals. It has two clear operating modes: Live Tracking for the current event and Event Replay for reviewing positions already stored in the Google Tracking sheet.

Live Tracking

Live Tracking reads the latest accepted position for each entrant from the separate Tracking Google connection. The page refreshes the live positions at regular intervals and keeps the map focused on the current event, selected control, or selected entrant.

Live positions are last known positions. A delayed or stale marker means that a newer report has not yet been received; it does not prove that the entrant has stopped.

Entrants

Opens the Entrants card. Select All Entrants, Controls, or one entrant. Selecting an entrant centres the map and opens the entrant card.

Settings

Sets entrant dot size, marker labels, the default selected-entrant trail, and the Controls View zoom level.

Tracking — desktop only

Opens the Tracking setup card for event upload, the Google tracking log, mobile Tracking links, and the independent Tracking Apps Script connection.

Entrant dots and colours

Green — Active
Recent tracking information is available.
Orange — Delayed
The next report is later than expected.
Flashing orange — Stale
No sufficiently recent report has been received; the dot remains at the last known position.
Grey — Past or Finished
The entrant has passed the selected control or completed the route.
Red — Selected entrant
The entrant card is open and that entrant is being followed.

Entrant card and trail

The entrant card shows rally number, entrant name, current tracking status, latest speed, and reported GPS accuracy. Trail choices are None, 5 min, 10 min, and All. Closing the card clears the selected state.

Centre control and Controls View

Select ◎ to restore the appropriate map view: the full event, the selected control, or the selected entrant. In Controls View, grey entrants have passed the chosen control while delayed and stale statuses remain visible.

Event Replay

Select Event Replay to leave Live Tracking and review the recorded positions stored in the Google Tracking sheet. Replay and Live Tracking are separate modes; replay positions are never mixed with current live positions.

For a previous event, first open the saved rally project and set the required Day date to the date of the recorded Tracking run. Event Replay uses that project date to find the matching GPS history in Google.

Replay uses the stored GPS Time. It does not use Received Time, rally-number order, or invented movement between records.

Choose what to replay

  • All entrants replays every entrant that has matching recorded history.
  • One entrant focuses on that entrant while retaining the normal entrant display behaviour.
  • The card shows the available recorded history range.
  • Select the required start time within that range.

Replay speed

Choose 1×, 2×, 5×, or 20×. The default is 1×. While Replay mode is open, the quick speed buttons beside the REPLAY indicator change speed immediately without restarting the replay.

Replay controls

  • Start / Pause starts the replay or freezes it at the exact current replay time.
  • Stop freezes the current replay for inspection.
  • Reset returns to the selected entrant, selected start time, and selected speed so the same selection can be replayed again.
  • Return to Live cancels Replay mode, clears replay-only display, fetches the latest positions, and resumes normal Live Tracking.

How recorded positions move

The page reads the available history when Replay is opened, then runs the replay locally in the browser. Each marker changes when its next stored GPS timestamp is reached.

  • Records with the same or very close GPS timestamps appear to move together.
  • Different timestamps produce the corresponding staggered movement.
  • If a record is missing, the entrant remains at the last recorded position.
  • There is no bridging, interpolation, or invented movement between Sheet records.
  • Delayed uploads still appear at their correct historical GPS time.

The winking REPLAY indicator shows that Replay is running. It remains visible but steady when replay is paused or stopped, and disappears on Return to Live.

Tracking event upload

Select Upload tracking data to send a Tracking-specific copy of the active rally, entrants, day, route, and mapped route to the separate Tracking Google connection. The entrant rally numbers in the event package must match the rally numbers stored in the Tracking sheet for Replay to display them.

Mobile tracking and network connection

The mobile Tracking app does not need a continuous network connection. While the tracker is running, positions are recorded on the phone.

  • When a network connection is available, positions can be sent to the Tracking log as they are recorded.
  • When the phone is offline, the positions remain queued on the phone and are uploaded after a network connection returns.
  • After reconnecting, keep the Tracking app open until the queued-record count has returned to 0 before closing it.
Event use: Tracking does not depend on continuous mobile coverage. This supports using the STC Recorder in flight mode, with queued Tracking positions uploaded after the phone is reconnected.

Normal event workflow

  1. Upload the active Tracking event from the desktop Tracking card.
  2. Share the mobile Tracking link with the required entrant or tracking phone.
  3. Run Live Tracking during the event.
  4. After reconnecting, allow the queued-record count to return to zero before closing the mobile tracker.
  5. After the event, select Event Replay and review all entrants or one entrant from the required start time.
  6. Select Return to Live when the replay review is complete.
